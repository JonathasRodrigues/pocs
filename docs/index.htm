2. Contexto e Objetivo

A empresa necessita padronizar uma biblioteca de componentes UI para desenvolvimento de aplicativos mobile com React Native e TypeScript. A escolha impacta:

  • Velocidade de desenvolvimento e produtividade do time
  • Consistência visual entre telas e produtos
  • Alinhamento entre times de design e desenvolvimento
  • Manutenção e evolução a longo prazo
  • Performance dos aplicativos em produção

7. Análise Detalhada por Critério

7.1 Maturidade e Estabilidade (20%)

gluestack-ui (5/5): Versão estável v3, prodution-ready. Evolução do NativeBase com 15+ anos da GeekyAnts. Histórico claro de releases sem breaking changes frequentes.

HeroUI Native (2/5): Beta (RC1). Primeira versão para React Native. 13 beta releases + 1 RC. Mudanças de API esperadas antes da estabilidade.

7.2 Comunidade e Suporte (15%)

gluestack-ui (4/5): ~4.900 stars, Discord ativo, backed by GeekyAnts, documentação completa, canal YouTube com tutoriais.

HeroUI Native (3/5): ~2.965 stars (native), ~28.000 stars (web), Discord compartilhado, documentação em construção.

7.3 Design System / Figma (15%)

gluestack-ui (5/5): Kit Figma com 30+ componentes e 4536 styles. Plugin Figma dedicado. Spec sheets com estrutura, propriedades e use cases. Design tokens 1:1 com código.

HeroUI Native (4/5): Kit Figma V3 disponível. Design tokens definidos. Sem plugin Figma dedicado.

7.4 Performance (15%)

Ambos (4/5): gluestack usa NativeWind com estilos pré-compilados. HeroUI claims <16ms render. Ambos tree-shakable. Benchmarks reais devem ser coletados em dispositivo físico.

7.5 Developer Experience (15%)

gluestack-ui (5/5): CLI automatizado, design tokens via CSS variables (bg-primary-500), theming automático, 661 LOC para 4 telas.

HeroUI Native (4/5): Com Uniwind configurado, usa className efetivamente. Componentes reais (Button, Switch). Porém: setup manual, sem design tokens (bg-[#006FEE]), theming manual.

7.6 Customização (10%)

gluestack-ui (5/5): Copy-paste = 100% do código é seu. Sem vendor lock-in.

HeroUI Native (4/5): Slots customizáveis, Tailwind Variants. Limitado ao que a API expõe.

9. Recomendação Final

Recomendação: gluestack-ui v3

Adotar como biblioteca padrão de componentes UI para aplicativos mobile React Native.

Motivos principais:

  1. Estabilidade: Versão estável v3 vs beta RC1
  2. Produtividade: 24% menos código com design tokens integrados
  3. Setup: CLI automatizado em ~5 minutos
  4. Design System: Kit Figma completo com plugin + spec sheets
  5. Ownership: Modelo copy-paste = controle total sem vendor lock-in

Pontos fortes reconhecidos do HeroUI Native:

  • Componentes reais (Button, Switch) com boa tipagem
  • Bundle ~7% menor
  • Tailwind CSS v4 (mais recente)
  • Se atingir v1 estável com design tokens, será alternativa forte

Métricas de Sucesso

  1. Tempo de desenvolvimento de telas: deve ser ≤ padrão atual
  2. Bugs de UI: não devem aumentar significativamente
  3. Satisfação do time de design: feedback positivo sobre alinhamento Figma-código
  4. Performance: render time < 100ms para telas comuns
